## 5. Known issues, TODOs, and intentional deviations (with reasons)

1. **FIFA Card doesn't show Club or Nation anywhere visible.** The generated card image doesn't depict them, and no caption was added when the card switched from the hand-built version (which did show them) to the image. `fifaCard.club`/`.nation` sit unused in the data. *Not yet fixed — flagged, awaiting your call on whether/how to add them back (e.g. a small line near the card).*
2. **DESIGN_BRIEF's core FIFA Card labeling rule — "primary label = real skill, secondary = football code" — isn't realized anywhere.** The `skill`/`descriptor` fields exist in `content.ts` specifically for this but became orphaned when the hand-built stat grid was replaced by the baked-in image (confirmed via grep: zero usages). The "Numbers" hover panel shows `code — reasoning` only, never `skill`. *Not yet fixed.*
3. **Tier ("Ones to Watch") isn't visible anywhere** for the same reason as #1 — it was on the hand-built version, lost when that was replaced by the image.
4. **The "corner ribbon" ("Currently building: Frontage") is a caption below the card, not an actual corner ribbon.** Deliberate: the generated image's own crystal-wing artwork occupies the top-right corner where a ribbon would sit, and overlaying one there would visually clash with real artwork rather than empty card space.
5. **Card flip → hover-reveal side panels.** Deliberate, explicit user request mid-build, not a bug. Means the brief's literal "flip or reveal interaction... front = card face, back = short bio" line is satisfied in spirit (reveal exists) but not in its specified mechanism (no flip).
6. **`motion.ts` tokens are under-adopted** (§3). Real inconsistency risk: new components (`FifaCard`, `MatchClock`) feel deliberately paced; older ones (`FadeIn`, `Magnetic`, `ScrambleText`) still use whatever was hardcoded before the football-theme work. Not visually broken, just not the unified system `MOTION.md` describes.
7. **`motion.ts` exports `motionTokens`, not `motion`** as `MOTION.md`'s snippet literally names it — deliberate, to avoid colliding with `import { motion } from 'framer-motion'` used throughout the codebase. Values are identical to spec, only the identifier differs.
8. **A real bug was caught and fixed during this work, not left in:** `motion.ts`'s `ease` values were originally stored as raw CSS `cubic-bezier()` strings, which neither GSAP nor Framer Motion actually parse in that format — both were silently falling back to default easing. Fixed to the number-array format Framer Motion expects; GSAP call sites use native GSAP eases instead.
9. **Orphaned but harmless:** `About.tsx`, `Skills.tsx`, `Stats.tsx` (components) and `about`, `skills`, `stats`, `certifications` (data) — no longer imported by `App.tsx`, left in place as-is rather than deleted, consistent with how this project has handled superseded code all along (e.g. `GenerativeArt`/`LoanFlowVisual` are similarly still imported by `ProjectCard.tsx` but currently unreachable, since no project in the current `projects` array uses those `visual` values anymore — only `WireframeVisual` is live, via the 3D Interactive Website card).
10. **Not verified live in a real browser this session** — the automated browser tool used throughout this build has had repeated, confirmed-non-code-related rendering issues today (screenshots returning blank/black frames, `requestAnimationFrame` suspending while the pane is reported "hidden," and one instance of the viewport itself reporting 0×0). Every claim above was checked via DOM/computed-style inspection, `grep`, or the build/lint/type-check pipeline — genuinely reliable, but not the same as eyes on a rendered page. Worth a real look in your own browser, especially the FIFA Card's photo/caption layout.
